# Postponement Reasons

**Purpose:** Catalog of reasons why features get postponed and criteria for reactivation.  
**Last Updated:** November 27, 2025  
**Maintenance:** Product Manager / Tech Lead

## Overview

This folder contains standardized categories for why features are postponed, helping maintain consistency in decision-making and documentation.

## Key Files

- `Condition_Dependencies.md` - Feature A depends on Feature B
- `Resource_Constraints.md` - Team bandwidth, budget limitations
- `Technical_Blockers.md` - Missing third-party services, infrastructure needs
- `Business_Justification.md` - Low customer demand, unclear ROI
- `Market_Validation_Needed.md` - Feature needs customer feedback first
- `Infrastructure_Requirements.md` - Database/system not ready
- `Reactivation_Criteria.md` - When to bring features back

## Common Postponement Categories

### 1. Dependency-Based
- Feature requires another feature to be completed first
- Waiting on external API availability
- Database schema changes needed first

### 2. Resource-Based
- Team bandwidth insufficient
- Budget not allocated
- Skills gap on team

### 3. Business-Based
- Low customer demand
- Revenue potential unclear
- Competitive threat not imminent

### 4. Technical-Based
- Infrastructure not ready
- Third-party service not available
- Security concerns need resolution

## When to Use This Folder

- When deciding to postpone a feature
- When reviewing postponed features for reactivation
- When explaining decisions to stakeholders
- When planning future phases
